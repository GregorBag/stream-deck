# Протокол панели, версия 1

Транспорт: USB COM, 115200 бод, 8 бит данных, без чётности, один стоповый бит, без аппаратного управления потоком. Реализованы кодек, сеанс Python, программная модель платы и COM-транспорт Qt; физическая плата пока недоступна для проверки.

## Формат

ASCII, одна строка — одно сообщение, LF в конце. Приёмник также допускает CRLF. Поля разделены одним пробелом. Максимум 192 байта перед LF (включая необязательный CR). Некорректная строка отбрасывается целиком; следующая строка обрабатывается независимо. Слишком длинная строка не накапливается в памяти и пропускается до LF.

| Направление | Сообщение | Назначение |
|---|---|---|
| Приложение → плата; плата → приложение | `HELLO DJ_POLTORASHKA 1` | Имя устройства и версия |
| Приложение → плата | `PING 42` | Проверка связи |
| Плата → приложение | `PONG 42` | Ответ с тем же номером |
| Плата → приложение | `STATE 0 1023 512 1 8001` | Четыре положения ползунков и маска кнопок |
| Приложение → плата | `LEDS 50 <144 hex-цифры>` | Предел яркости и 24 RGB-цвета |

Десятичные поля не содержат знака, дробной части и пробелов. Принимаются оба регистра hex-цифр; отправитель использует заглавные.

## Подключение

После открытия порта приложение посылает HELLO. Плата отвечает своим HELLO и полным STATE. При несовпадении имени или версии сообщения управления не применяются. Плата также объявляет HELLO после собственного перезапуска; приложение начинает синхронизацию заново.

При подключении или перезапуске сбрасываются накопленный фрагмент строки, предыдущая маска кнопок и сведения об отправленном кадре подсветки. Первое STATE устанавливает исходную маску: удерживаемые кнопки не вызывают нажатий. Затем нажатие определяется переходом бита из 0 в 1, отпускание обновляет маску.

После успешного HELLO приложение один раз отправляет полный актуальный кадр подсветки.

## STATE

Поля ползунков соответствуют P1–P4, целые значения АЦП от 0 до 1023. Приложение нормализует их в диапазон 0–1; подхват физического положения выполняется отдельно от кодека.

Маска кнопок: ровно четыре hex-цифры, бит 0 соответствует SW1, бит 15 — SW16. Единица означает нажатую кнопку. `8001` означает SW1 и SW16. Плата передаёт полное состояние после изменения ползунков или обработанного состояния кнопок. Подавление дребезга и шума относится к прошивке.

## LEDS

Первое поле — общая яркость, целое число от 0 до 50%. Оно нужно также для автономного белого мигания при потере связи. Далее идут 24 цвета RRGGBB без пробелов: сначала LED1–LED8 по часовой стрелке от левого нижнего угла, затем подсветка SW1–SW16. Прошивка преобразует этот логический порядок в физический порядок цепочки.

RGB уже масштабированы приложением. Плата не умножает их на яркость повторно. Компоненты должны быть от 0 до round(255 × яркость / 100), например при 50% — до 128. Некорректный кадр отклоняется целиком.

Приложение посылает LEDS только при изменении итоговых RGB или предела яркости. Изменение настроек, дающее тот же итоговый кадр и предел, отправки не требует. Heartbeat не вызывает повторную отправку цветов. Исключение — полная синхронизация после нового подключения или перезапуска платы.

Кадр отмечается отправленным только после успешной записи всей строки в транспорт. При ошибке или частичной записи следующий сеанс начинает синхронизацию заново. Протокол версии 1 не содержит подтверждения применения кадра и контрольной суммы; кодек обнаруживает ошибки формата и диапазонов, но не гарантирует обнаружение любой подмены допустимых данных.

## Проверка связи

Приложение посылает PING каждые 500 мс, номера 0–65535 циклически. Плата немедленно отвечает PONG с тем же номером. Ответы сопоставляются с ожидаемыми номерами. Отсутствие подтверждённого обмена в течение 2000 мс означает потерю связи. Некорректные сообщения не продлевают соединение.

Плата отслеживает получение PING. После 2000 мс без него только LED1–LED8 мигают белым: 500 мс свет / 500 мс темнота, с последним полученным пределом яркости. До первого LEDS предел — 50%. Подсветка кнопок не участвует в мигании. После восстановления требуется полная синхронизация цветов.

## Программный стенд

`PanelSession` принимает функцию записи байтов и явное монотонное время в миллисекундах. `start` начинает проверку устройства, `receive` разбирает поступившие байты, `tick` обслуживает heartbeat и тайм-ауты. Реальный транспорт должен вызывать `tick` регулярно, выполнять запись без повторного входа в методы сеанса и закрывать повреждённое соединение после ошибки записи. Сеанс сам не запускает поток и не открывает COM-порт.

Сеанс возвращает полные STATE и события нажатий SW1–SW16 для существующего маршрутизатора. Положения ползунков возвращаются в исходном виде: подхват и применение громкости выполняются отдельным компонентом. Первое состояние после HELLO устанавливает исходную маску без событий нажатия.

Сразу после HELLO отправляется первый PING, далее — один раз в 500 мс. Только PONG с ожидаемым номером продлевает сеанс приложения. Дубликаты, устаревшие ответы и STATE не маскируют потерю heartbeat. Плата отдельно отслеживает PING, поэтому при односторонней потере связи тайм-ауты сторон могут наступить в разное время. Перезапуск платы запускает новый обмен HELLO и полную синхронизацию.

`PanelEmulator` моделирует ответы платы, изменение органов управления и автономное мигание. `PanelSimulation` соединяет стороны очередями байтов, позволяет дробить чтение и отключать каждое направление обмена. На каждое повторное подключение создаётся чистый транспортный поток: накопленные фрагменты предыдущего соединения сбрасываются с обеих сторон.

Запускаемый пример из корня проекта:

```powershell
.\desktop_app\.venv\Scripts\python.exe -m dj_poltorashka.panel.simulation
```

Пример использует виртуальное время, не ждёт реальные две секунды и не управляет звуком Windows. Он показывает подключение, состояния четырёх ползунков, нажатия, отсутствие повторной отправки цветов при heartbeat, потерю связи, белое мигание периметра и восстановление без ложных нажатий. Консольный стенд запускается отдельно от графического приложения.

## Подключение в приложении

В «Настройки → Подключение панели» доступны выбор COM-порта, обновление списка, подключение и отключение. Выбранный порт действует в текущем запуске приложения. При потере связи приложение закрывает порт и раз в секунду пробует открыть тот же порт; другие устройства автоматически не перебираются. Ручное отключение отменяет повторные попытки.

Порт обслуживается в отдельном QThread через [Qt Serial Port](https://doc.qt.io/qtforpython-6/PySide6/QtSerialPort/QSerialPort.html). Обмен работает без блокирующих ожиданий, 115200, 8N1; чтение и очередь отправки ограничены 4096 байтами. Перед HELLO после открытия реального порта предусмотрена пауза 2 секунды для возможного перезапуска Nano, затем действует отдельный тайм-аут протокола. Функция записи подтверждает приём строки очередью Qt; асинхронная ошибка записи закрывает сеанс и приводит к полной синхронизации при следующем подключении.

Выбор «Имитатор платы» позволяет проверить кнопки существующей вкладки симулятора через транспорт и протокол. Программируемые кнопки, mute и пресеты передают полное состояние с нажатием и отпусканием, затем возвращаются в обычный маршрутизатор приложения. Ползунки графического симулятора пока работают напрямую; реальные положения от платы принимаются, но не меняют громкость до отдельной реализации подхвата.

Подсветка рассчитывается по конфигурации, глобальным цветам и состоянию воспроизведения. Изменения mute, выбранного пресета, назначения звука, запуск/окончание/ошибка воспроизведения и сохранение цветов обновляют желаемый кадр. На провод уходят только изменения; при подключении отправляется один полный кадр.

Сеанс, транспорт, имитатор, фоновый поток и связь с интерфейсом проверяются без платы. Физический COM-порт, поведение Nano после открытия, питание и тайминги светодиодов ещё не проверены. Подхват физических ползунков и прошивка остаются следующими этапами.
