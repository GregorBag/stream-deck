# Протокол панели, версия 1

Транспорт: USB COM, 115200 бод, 8 бит данных, без чётности, один стоповый бит, без аппаратного управления потоком. На этом этапе реализован кодек Python, без открытия реального COM-порта.

## Формат

ASCII, одна строка — одно сообщение, LF в конце. Приёмник также допускает CRLF. Поля разделены одним пробелом. Максимум 192 байта перед LF (включая необязательный CR). Некорректная строка отбрасывается целиком; следующая строка обрабатывается независимо. Слишком длинная строка не накапливается в памяти и пропускается до LF.

| Направление | Сообщение | Назначение |
|---|---|---|
| Приложение → плата; плата → приложение | `HELLO DJ_POLTORASHKA 1` | Имя устройства и версия |
| Приложение → плата | `PING 42` | Проверка связи |
| Плата → приложение | `PONG 42` | Ответ с тем же номером |
| Плата → приложение | `STATE 0 1023 512 1 8001` | Четыре положения ползунков и маска кнопок |
| Приложение → плата | `LEDS 50 <144 hex-цифры>` | Предел яркости и 24 RGB-цвета |

Десятичные поля не содержат знака, дробной части и пробелов. Принимаются оба регистра hex-цифр; отправитель использует заглавные.

## Подключение

После открытия порта приложение посылает HELLO. Плата отвечает своим HELLO и полным STATE. При несовпадении имени или версии сообщения управления не применяются. Плата также объявляет HELLO после собственного перезапуска; приложение начинает синхронизацию заново.

При подключении или перезапуске сбрасываются накопленный фрагмент строки, предыдущая маска кнопок и сведения об отправленном кадре подсветки. Первое STATE устанавливает исходную маску: удерживаемые кнопки не вызывают нажатий. Затем нажатие определяется переходом бита из 0 в 1, отпускание обновляет маску.

После успешного HELLO приложение один раз отправляет полный актуальный кадр подсветки.

## STATE

Поля ползунков соответствуют P1–P4, целые значения АЦП от 0 до 1023. Приложение нормализует их в диапазон 0–1; подхват физического положения выполняется отдельно от кодека.

Маска кнопок: ровно четыре hex-цифры, бит 0 соответствует SW1, бит 15 — SW16. Единица означает нажатую кнопку. `8001` означает SW1 и SW16. Плата передаёт полное состояние после изменения ползунков или обработанного состояния кнопок. Подавление дребезга и шума относится к прошивке.

## LEDS

Первое поле — общая яркость, целое число от 0 до 50%. Оно нужно также для автономного белого мигания при потере связи. Далее идут 24 цвета RRGGBB без пробелов: сначала LED1–LED8 по часовой стрелке от левого нижнего угла, затем подсветка SW1–SW16. Прошивка преобразует этот логический порядок в физический порядок цепочки.

RGB уже масштабированы приложением. Плата не умножает их на яркость повторно. Компоненты должны быть от 0 до round(255 × яркость / 100), например при 50% — до 128. Некорректный кадр отклоняется целиком.

Приложение посылает LEDS только при изменении итоговых RGB или предела яркости. Изменение настроек, дающее тот же итоговый кадр и предел, отправки не требует. Heartbeat не вызывает повторную отправку цветов. Исключение — полная синхронизация после нового подключения или перезапуска платы.

Кадр отмечается отправленным только после успешной записи всей строки в транспорт. При ошибке или частичной записи следующий сеанс начинает синхронизацию заново. Протокол версии 1 не содержит подтверждения применения кадра и контрольной суммы; кодек обнаруживает ошибки формата и диапазонов, но не гарантирует обнаружение любой подмены допустимых данных.

## Проверка связи

Приложение посылает PING каждые 500 мс, номера 0–65535 циклически. Плата немедленно отвечает PONG с тем же номером. Ответы сопоставляются с ожидаемыми номерами. Отсутствие подтверждённого обмена в течение 2000 мс означает потерю связи. Некорректные сообщения не продлевают соединение.

Плата отслеживает получение PING. После 2000 мс без него только LED1–LED8 мигают белым: 500 мс свет / 500 мс темнота, с последним полученным пределом яркости. До первого LEDS предел — 50%. Подсветка кнопок не участвует в мигании. После восстановления требуется полная синхронизация цветов.

Кодек, выделение строк и подавление дублирующихся LEDS проверяются без платы. Таймеры соединения, маршрутизация кнопок, работа COM-порта и прошивка реализуются следующими небольшими этапами.
